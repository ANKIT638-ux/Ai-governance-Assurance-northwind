# AI Security & Governance Assurance System — Northwind Retail (fictional)
 
**A portfolio project for AI security / risk & compliance roles**
 
This project builds that assurance loop for a
fictional retailer's AI estate: inventory → risk → controls → evidence → executive reporting,
with one real technical finding walked all the way through so the system isn't just a stack of
templates.

## The scenario
 
**Northwind Retail** is a mid-sized retailer running six AI systems. The project started with
four systems; I later added two more of my own which are MarketPulse and ExpenseAuditor. Which was done to test
whether I could apply the same governance framework to a system I hadn't already designed
around.
 
1. **NorthwindHR-Bot** — internal employee chatbot for HR/IT questions
2. **Nova** — customer support assistant (external facing, handles PII and refunds)
3. **DevAssist** — coding agent used by engineering (repo read/write, CI access)
4. **MerchIQ** — decision support model for inventory/pricing recommendations
5. **MarketPulse** — marketing AI that drafts and sends personalized email/SMS campaigns
6. **ExpenseAuditor** — finance AI that reviews and auto approves employee expense claims
## The traceability thread (the point of the whole exercise)
 
A red team exercise found that Nova, the customer-support
assistant, could be manipulated through **indirect prompt injection** instructions hidden inside
a customer's own support ticket and into disclosing another customer's account details. That single
technical finding is followed through this entire system:
 
**Attack demonstrated → risk logged → controls mapped → evidence defined → gap found → remediation
ticket → retest → risk register closed out.**
 
See `06-traceability-thread.md` for the full walk-through — it's the strongest single artifact in
this portfolio and the one worth walking an interviewer through directly.
 
## Frameworks used
 
- [NIST AI Risk Management Framework (AI RMF 1.0)](https://www.nist.gov/itl/ai-risk-management-framework) and the Generative AI Profile (NIST AI 600-1)
- [OWASP Top 10 for LLM Applications (2025)](https://owasp.org/www-project-top-10-for-large-language-model-applications/)
- [MITRE ATLAS](https://atlas.mitre.org/)
All three are used together deliberately, mirroring how a real compliance function would work:
NIST AI RMF gives the governance *lifecycle* (Govern/Map/Measure/Manage), OWASP gives the
*vulnerability* vocabulary, and ATLAS gives the *adversary* vocabulary, what a real attacker
actually does, mapped to tactics and techniques.
